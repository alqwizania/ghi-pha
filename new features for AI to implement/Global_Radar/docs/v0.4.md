# SehaRadar v0.4 — Per-Article URL Extraction

> Extract individual outbreak report URLs from ChangeDetection.io JS-injected snapshots and populate the `url` field distinctly from `source_link`.

---

## Problem

All 44 ChangeDetection.io sources currently set both `url` and `source_link` to the **same value** — the monitored page URL (e.g., `https://www.who.int/emergencies/disease-outbreak-news`). Individual article URLs are lost.

A JS injection script was added to ChangeDetection.io watches that embeds per-article URLs into the snapshot text:

```javascript
const checkTime = new Date().toLocaleString();
document.querySelectorAll('a').forEach(el => {
  el.innerText = `${el.innerText} [${el.href}] [Checked: ${checkTime}]`;
});
```

But no parser extracts these URLs. They either get silently dropped (WHO parser) or included as noise in titles/headlines (CDC, generic parsers).


### Injected Pattern

Every `<a>` tag's inner text becomes: `OriginalText [URL] [Checked: M/D/YYYY, H:MM:SS AM/PM]`

### Key Observations

| Observation | Detail |
|-------------|--------|
| Pattern is consistent | Always `[URL] [Checked: timestamp]` — regex-friendly |
| Pipe `\|` survives in WHO DON | WHO parser structural logic still works on cleaned text |
| Non-injected brackets safe | `[809 kB]` does not match `[http...]`, won't be stripped |
| Trailing text after `[Checked:]` | e.g., `Disease Outbreak News` — regex must not be greedy |
| Some lines are URL-only | China CDC: anchor text is just a date (`2026-02-10`) |

## Semantic Distinction (Post-Implementation)

| NocoDB Field | Meaning | Example |
|--------------|---------|---------|
| `source_link` | The monitored page URL (the ChangeDetection.io watch target) | `https://www.who.int/emergencies/disease-outbreak-news` |
| `url` | The individual article/outbreak report URL | `https://www.who.int/.../item/2026-DON595` |

## Architecture: Universal Pre-processing Layer

Rather than modifying each parser individually, add a **single pre-processing step** in `BaseParser` that all parsers inherit. This runs before any parser-specific logic.

```
ChangeDetection snapshot (raw text with JS-injected URLs)
        |
        v
  BaseParser.preprocess_line()          <-- NEW: universal step
  |-- Extract [https://...] URLs per line
  |-- Strip [Checked: ...] timestamps
  +-- Return (clean_text, article_url)
        |
        v
  Parser-specific logic (WHO/CDC/generic)
  |-- Works on CLEAN text (existing logic unchanged)
  +-- Sets link = extracted_article_url
        |
        v
  Workflow: _analyze_items()
  |-- source_link = source_url (monitored page)
  +-- url = item.link (individual article)
        |
        v
  NocoDB storage (url != source_link)
```

### Why NOT Consolidate Parsers

- **WHO parser** still adds real value — extracts structured date, title, location from pipe-delimited format
- **CDC parser** extracts dates and locations with CDC-specific regex patterns
- **AI parser** would cost money per API call x 44 sources x 10 items = 440 LLM calls per scan
- Pre-processing gives ALL parsers URL extraction for free via inheritance

## Implementation Plan

### Regex

```python
INJECTED_PATTERN = re.compile(r'\s*\[(https?://[^\]]+)\]\s*\[Checked:\s*[^\]]*\]')
```

Correctly handles all 4 sample formats:
- Matches `[http://...]` and `[https://...]` followed by `[Checked: ...]`
- Does NOT match `[809 kB]` (no `http` prefix)
- Captures the URL for extraction
- Strips cleanly, leaving trailing text intact

### Files to Change (6 files, ~80 lines)

#### 1. `parsers/base_parser.py`

Add to `BaseParser`:

```python
INJECTED_PATTERN = re.compile(r'\s*\[(https?://[^\]]+)\]\s*\[Checked:\s*[^\]]*\]')

def preprocess_line(self, line: str) -> tuple[str, Optional[str]]:
    """Strip JS-injected [URL] [Checked:...] artifacts.
    Returns (clean_text, best_article_url_or_None)"""
    urls = INJECTED_PATTERN.findall(line)
    clean = INJECTED_PATTERN.sub('', line)
    clean = ' '.join(clean.split())  # collapse whitespace
    # Pick most specific URL (longest path)
    article_url = max(urls, key=len) if urls else None
    return clean, article_url
```

Add `article_url` field to `RawFinding` model and expose it in `to_dict()`.

#### 2. `parsers/who_parser.py`

Call `preprocess_line()` per line before the `|` split:

```python
clean_line, article_url = self.preprocess_line(line)
# Existing pipe-split logic works on clean_line
# ...
link = article_url or source_url or "https://..."
```

#### 3. `parsers/cdc_parser.py`

Same pattern — eliminates false date matches from `[Checked:]` timestamps:

```python
clean_line, article_url = self.preprocess_line(line)
# Existing logic on clean_line
link = article_url or source_url or "https://..."
```

#### 4. `parsers/generic_parser.py`

In `_parse_as_text()`:

```python
clean_line, article_url = self.preprocess_line(line)
link = article_url or source_url
```

#### 5. `workflows/unified_scan_workflow.py`

In `_analyze_items` (line ~401), pass both URLs separately:

```python
"source_link": source_url,                      # the monitored page (always)
"url": item.get("link", "") or source_url,      # the article URL (from parser)
```

#### 6. `tools/nocodb_client.py`

In `create_finding_v3`, make `url` and `source_link` write distinct values:

```python
"source_link": finding.get("source_link") or source_url,   # monitored page
"url": finding.get("url") or finding.get("source_link", ""),  # individual article
```
